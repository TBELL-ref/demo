화이트박스 테스트
(White-Box Testing)

소프트웨어의 내부 구조와 동작을 아는 상태에서 테스트를 수행하는 것으로, 코드를 기반으로 한 테스팅 기법입니다.
코드 검토를 비롯하여 경계조건, 결정, 경로 테스트 등 대상 소프트웨어에 적합한 테스트를 수행할 수 있습니다.

특히 화이트박스 테스트를 통해 소스코드에 잠재되어 있는 결함과 코딩 표준 위배사항 등을 사전에 검출하여,
소프트웨어의 안정성 강화와 동시에 오류 수정에 소요되는 비용을 절약할 수 있습니다.

  • 관점

    개발자 관점에서 코드의 작동 방식과 내부 로직을 봅니다.

  • 목적

    모든 문장과 논리 경로를 한 번 이상 실행해, 숨은 구조적 오류와 알고리즘 문제를 일찍 찾습니다.

  • 주요 단계

    주로 개발 초기의 단위 테스트와 통합 테스트 시점에 활용합니다.

주요 검사 종류

White-Box Testing

기초 경로 검사Basic Path Testing

순환 복잡도를 계산해 프로그램의 기본 실행 경로를 빠짐없이 테스트합니다.

V(G) = E − N + 2

제어 구조 검사Control Structure Testing

프로그램의 제어 구조를 따라 조건, 반복, 데이터의 흐름을 검사합니다.

  • 조건 검사

    모듈 안의 논리적 조건이 참과 거짓으로 올바르게 동작하는지 테스트합니다.

  • 루프 검사

    반복문의 구조와 반복 횟수의 한계값을 테스트합니다.

  • 데이터 흐름 검사

    변수가 어디서 정의되고 어디서 쓰이는지 추적합니다.

구문 커버리지 Statement Coverage

전체 실행 구문 중 최소 1회 이상 실행된 구문의 비율을 봅니다.

1개 테스트 · 참인 경우 하나로 if 안의 구문이 모두 실행됩니다.

결정·분기 커버리지 Decision / Branch Coverage

조건문의 참과 거짓 결과가 각각 최소 1회 이상 실행되게 합니다.

2개 테스트 · 참 한 번, 거짓 한 번으로 두 갈래를 모두 지납니다.

조건 커버리지 Condition Coverage

결정 안의 개별 조건식이 각각 참과 거짓을 모두 갖도록 테스트합니다.

2개 테스트 · A와 B는 참·거짓을 모두 갖지만, 결정은 거짓만 나와 참 갈래는 지나지 않습니다.

변경 조건/결정 커버리지 MC/DC

각 조건식이 전체 결정 결과에 독립적으로 영향을 주는지 검증합니다. 항공우주 등 안전 필수(Safety-Critical) 시스템에서 주로 요구됩니다.

3개 테스트 · A만 바꾼 쌍과 B만 바꾼 쌍에서 결과가 각각 달라지는지 확인합니다.

업무 범위

티벨의 화이트박스 테스트 전문가는 다양한 업무영역에서의 화이트박스 테스트 경험을 갖추고 있으며,
특히 고객 맞춤형 도구를 활용하여 최상의 결과를 제공하고 있습니다.

자주 묻는 질문

정적 분석(정적 테스트)은 무엇인가요?

코드를 실행하지 않고 소스코드 자체를 검토해 코딩 규칙 위배와 잠재 결함 등을 찾는 방법입니다. 도구를 이용한 자동 점검과 사람의 코드 리뷰를 함께 사용합니다.

화이트박스 테스트를 하면 무엇이 좋아지나요?

소스코드에 잠재된 결함과 코딩 표준 위배를 사전에 검출해 소프트웨어의 안정성을 강화하고, 오류 수정에 드는 비용을 줄일 수 있습니다.

블랙박스 테스트와 무엇이 다른가요?

블랙박스 테스트는 내부를 보지 않고 입력과 출력으로 기능을 검증하고, 화이트박스 테스트는 코드를 직접 보고 내부 로직을 검증합니다. 블랙박스 테스트 보기

어떤 제품에 특히 필요한가요?

자동차, 임베디드, 금융처럼 작은 오류가 큰 사고로 이어질 수 있어 높은 신뢰성이 요구되는 분야에서 특히 중요합니다.
