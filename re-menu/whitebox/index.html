화이트박스 테스트
(White-Box Testing)

소프트웨어의 내부 구조와 동작을 아는 상태에서 테스트를 수행하는 것으로, 코드를 기반으로 한 테스팅 기법입니다.
코드 검토를 비롯하여 경계조건, 결정, 경로 테스트 등 대상 소프트웨어에 적합한 테스트를 수행할 수 있습니다.

특히 화이트박스 테스트를 통해 소스코드에 잠재되어 있는 결함과 코딩 표준 위배사항 등을 사전에 검출하여,
소프트웨어의 안정성 강화와 동시에 오류 수정에 소요되는 비용을 절약할 수 있습니다.

관점
개발자
목적
모든 문장 · 경로 1회 이상 실행
주요 단계
단위 · 통합 테스트

주요 검사 종류

Basic Path

  • 기초 경로 검사Basic Path Testing

    순환 복잡도로 기본 실행 경로를 모두 테스트합니다.

    V(G) = E − N + 2

제어 구조 검사 Control Structure Testing

  • 조건 검사Condition Testing

    논리적 조건이 참과 거짓으로 맞게 동작하는지 봅니다.

  • 루프 검사Loop Testing

    반복문의 구조와 반복 횟수의 한계값을 봅니다.

  • 데이터 흐름 검사Data Flow Testing

    변수가 정의되고 쓰이는 흐름을 추적합니다.

검증 기준 · 커버리지

같은 로그인 규칙을 기준마다 몇 번, 어떤 입력으로 테스트해야 하는지 비교합니다.

아이디 맞음그리고비밀번호 맞음→로그인하나라도 틀리면 거부

  1. 구문 커버리지Statement

    로그인 문장이 한 번만 실행되면 됩니다.

    1개 테스트

    1. 아이디 ✓ 비밀번호 ✓로그인

  2. 결정 · 분기 커버리지Decision / Branch

    로그인되는 경우와 거부되는 경우를 한 번씩 봅니다.

    2개 테스트

    1. 아이디 ✓ 비밀번호 ✓로그인
    2. 아이디 ✗ 비밀번호 ✗거부

  3. 조건 커버리지Condition

    아이디와 비밀번호가 각각 한 번씩 맞고, 한 번씩 틀리게 합니다.

    2개 테스트

    1. 아이디 ✓ 비밀번호 ✗거부
    2. 아이디 ✗ 비밀번호 ✓거부

  4. 변경 조건 / 결정 커버리지MC/DC

    아이디만, 비밀번호만 바꿔도 결과가 바뀌는지 확인합니다.

    3개 테스트

    1. 아이디 ✓ 비밀번호 ✓로그인
    2. 아이디 ✓ 비밀번호 ✗거부
    3. 아이디 ✗ 비밀번호 ✓거부
    항공우주 · 안전 필수

자주 묻는 질문

정적 분석(정적 테스트)은 무엇인가요?

코드를 실행하지 않고 소스코드 자체를 검토해 코딩 규칙 위배와 잠재 결함 등을 찾는 방법입니다. 도구를 이용한 자동 점검과 사람의 코드 리뷰를 함께 사용합니다.

화이트박스 테스트를 하면 무엇이 좋아지나요?

소스코드에 잠재된 결함과 코딩 표준 위배를 사전에 검출해 소프트웨어의 안정성을 강화하고, 오류 수정에 드는 비용을 줄일 수 있습니다.

블랙박스 테스트와 무엇이 다른가요?

블랙박스 테스트는 내부를 보지 않고 입력과 출력으로 기능을 검증하고, 화이트박스 테스트는 코드를 직접 보고 내부 로직을 검증합니다. 블랙박스 테스트 보기

어떤 제품에 특히 필요한가요?

자동차, 임베디드, 금융처럼 작은 오류가 큰 사고로 이어질 수 있어 높은 신뢰성이 요구되는 분야에서 특히 중요합니다.
