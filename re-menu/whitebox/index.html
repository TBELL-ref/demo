화이트박스 테스트

화이트박스 테스트는 소스코드의 내부 구조와 동작을 직접 보며 검증하는 테스트입니다. 숨은 결함과 코딩 표준 위배를 출시 전에 찾아냅니다.

  • 정적 분석
  • 코드 리뷰
  • 경로 테스트

  • 화이트박스 테스트
  • API 테스트
  • 성능 테스트

이럴 때 필요합니다

  • 높은 신뢰성이 필요한 제품일 때

  • 코딩 표준 준수 근거가 필요할 때

  • 기능은 통과했지만 코드가 불안할 때

  • 출시 후 수정 비용을 줄이고 싶을 때

두 가지 방법으로 코드를 봅니다

다양한 업무 영역의 경험과 고객 맞춤형 도구로 정적·동적 테스트를 수행합니다.

  • STATIC

    정적 테스트

    실행하지 않고 코드를 검토 · 코딩 규칙 점검과 리포트

  • DYNAMIC

    동적 테스트

    코드를 실행하며 검증 · 경계조건 · 결정 · 경로 테스트

코드 단계에서 결함을 잡으면 수정 비용이 줄어듭니다

  • 잠재 결함 사전 검출

    출시 전에 숨은 결함과 표준 위배를 찾습니다

  • 오류 수정 비용 절감

    늦게 발견할수록 커지는 수정 범위를 줄입니다

  • 고객 맞춤형 도구

    환경에 맞는 분석 도구를 골라 적용합니다

소스코드의 언어와 규모, 적용할 코딩 표준을 알려 주시면 분석 방법을 제안해 드립니다.

화이트박스 테스트란 무엇인가요?

소프트웨어의 내부 구조와 동작을 아는 상태에서 소스코드를 기반으로 수행하는 테스트 기법입니다. 코드 검토를 비롯해 경계조건, 결정, 경로 테스트 등 대상에 맞는 테스트를 수행하며, 동작의 결과뿐 아니라 실행되는 과정까지 살펴봅니다.

정적 분석(정적 테스트)은 무엇인가요?

코드를 실행하지 않고 소스코드 자체를 검토해 코딩 규칙 위배와 잠재 결함 등을 찾는 방법입니다. 도구를 이용한 자동 점검과 사람의 코드 리뷰를 함께 사용합니다.

블랙박스 테스트와 무엇이 다른가요?

블랙박스 테스트는 내부를 보지 않고 입력과 출력으로 기능을 검증하고, 화이트박스 테스트는 코드를 직접 보고 내부 로직을 검증합니다. 블랙박스 테스트 보기
