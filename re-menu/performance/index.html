DEFINITION

성능 테스트란?

성능 테스트(Performance Testing)는 시스템의 성능을 측정하고 분석해, 요구사항을 만족하는 데 필요한 처리량과 응답시간, 자원 사용 등의 지표를 산출하고 평가하는 테스트입니다.

개발된 시스템의 성능을 미리 검증하면 운영 중 발생할 수 있는 문제를 사전에 파악할 수 있습니다. 시스템의 한계와 임계점을 확인해 두면 안정적인 운영을 위한 기틀을 마련할 수 있습니다.

한 줄 정의
처리량·응답시간·자원 사용을 측정해 한계를 검증하는 테스트
핵심 지표
처리량(TPS), 응답시간, CPU·메모리 등 자원 사용률
함께 쓰는 말
부하 테스트, 스트레스 테스트, 성능 검증

WHEN YOU NEED IT

이럴 때 성능 테스트가 필요합니다

  • 서비스 오픈이나 이벤트 때 사용자가 한꺼번에 몰릴 예정이다
  • 차세대 시스템 전환이나 인프라 변경을 앞두고 있다
  • ‘느리다’는 사용자 불만이 늘고 있다
  • 서버를 얼마나 늘려야 할지 근거가 필요하다

SCOPE

성능 테스트의 종류

티벨은 각 분야의 전문가와 개발 연구소가 도구 선정부터 테스트까지 참여해, 목적에 맞는 성능 테스트를 수행합니다.

  • 부하 테스트

    예상되는 사용자 수와 요청량에서 응답시간과 처리량이 기준을 만족하는지 확인합니다.

  • 스트레스 테스트

    한계를 넘는 부하를 걸어 시스템이 어디서, 어떻게 무너지고 회복하는지 확인합니다.

  • 확장성 테스트

    서버나 자원을 늘렸을 때 성능이 그만큼 함께 늘어나는지 확인합니다.

  • 안정성 테스트

    오랜 시간 운영해도 메모리 누수나 성능 저하 없이 버티는지 확인합니다.

  • 볼륨 테스트

    대량의 데이터가 쌓였을 때도 처리 속도와 정확성이 유지되는지 확인합니다.

  • 구성 테스트

    설정과 환경 구성에 따라 성능이 어떻게 달라지는지 비교합니다.

FAQ

자주 묻는 질문

성능 테스트란 무엇인가요?

시스템의 처리량, 응답시간, 자원 사용 등 성능 지표를 측정하고 분석해, 요구사항을 만족하는지와 시스템의 한계·임계점을 검증하는 테스트입니다.

성능 테스트와 부하 테스트는 같은 말인가요?

부하 테스트는 성능 테스트의 한 종류입니다. 성능 테스트는 부하, 스트레스, 확장성, 안정성, 볼륨, 구성 테스트 등을 모두 포함하는 더 넓은 개념입니다.

언제 성능 테스트를 해야 하나요?

서비스 오픈이나 대규모 이벤트처럼 사용자가 몰리기 전, 차세대 시스템 전환이나 인프라 변경 전에 수행하는 것이 좋습니다. 운영 중 발생할 수 있는 문제를 사전에 파악할 수 있습니다.

어떤 도구를 사용하나요?

LoadRunner, Apache JMeter 등 대표적인 성능 테스트 도구를 사용하며, 대상 시스템과 목적에 맞춰 최적의 도구를 선정합니다.
