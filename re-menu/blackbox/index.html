DEFINITION

블랙박스 테스트란?

블랙박스 테스트(Black-Box Testing)는 소프트웨어의 요구사항과 명세서를 기반으로 테스트를 설계하고, 입력과 출력 데이터를 분석해 시스템이 올바르게 동작하는지 확인하는 동적 테스트입니다.

내부 구조를 몰라도 '이 입력에는 이 결과가 나와야 한다'는 기준으로 검증하기 때문에 실제 사용자의 관점에 가깝습니다. 버그와 오류를 찾는 것은 물론 사용성을 개선하고 사용자 만족도를 높이는 데에도 도움이 되며, 설계부터 구현까지 모든 개발 단계에서 수행할 수 있습니다.

한 줄 정의
요구사항 기준으로 입력·출력을 확인해 기능을 검증하는 테스트
관점
사용자 관점 (내부 코드는 보지 않음)
함께 쓰는 말
기능 테스트, 명세 기반 테스트

WHEN YOU NEED IT

이럴 때 블랙박스 테스트가 필요합니다

  • 기획서와 명세서대로 기능이 동작하는지 출시 전에 확인하고 싶다
  • 새 기능을 붙인 뒤 기존 기능이 망가지지 않았는지 걱정된다
  • 외부 시스템과 연결한 뒤 전체가 제대로 돌아가는지 확인해야 한다
  • 발주처 인수 전에 사용자 입장에서 최종 점검이 필요하다

TEST LEVELS

블랙박스 테스트로 무엇을 확인하나요?

티벨은 개발 명세서를 바탕으로 시나리오를 작성하고, 개발 단계에 맞춰 아래 테스트를 수행합니다.

  1. 인터페이스 테스트INTERFACE TEST

    모듈이나 시스템 사이에 데이터가 올바르게 오가는지 확인합니다.

  2. 통합 테스트INTEGRATION TEST

    따로 개발한 기능을 합쳤을 때 함께 제대로 동작하는지 검증합니다.

  3. 시스템 테스트SYSTEM TEST

    완성된 전체 시스템이 요구사항을 만족하는지 실제와 가까운 환경에서 확인합니다.

  4. 새니티 테스트SANITY TEST

    수정이나 빌드 직후 핵심 기능이 정상인지 빠르게 점검합니다.

  5. 회귀 테스트REGRESSION TEST

    변경 후에도 기존 기능이 망가지지 않았는지 다시 확인합니다.

  6. 인수 테스트ACCEPTANCE TEST

    사용자나 발주처 입장에서 제품을 받아들일 수 있는지 최종 확인합니다.

FAQ

자주 묻는 질문

블랙박스 테스트란 무엇인가요?

소프트웨어의 내부 코드를 보지 않고, 요구사항과 명세서를 기준으로 입력을 넣고 출력을 확인해 기능이 의도대로 동작하는지 검증하는 테스트 기법입니다.

기능 테스트와 같은 말인가요?

기능 테스트는 대부분 블랙박스 기법으로 수행되기 때문에 비슷한 의미로 쓰입니다. 다만 블랙박스는 '내부를 보지 않는다'는 접근 방식을 뜻하므로, 성능처럼 기능이 아닌 특성을 확인할 때도 쓰일 수 있습니다.

언제부터 블랙박스 테스트를 할 수 있나요?

요구사항과 명세서가 나오면 테스트 설계를 시작할 수 있어, 설계부터 구현까지 모든 소프트웨어 개발 단계에서 테스트가 가능합니다.

반복되는 회귀 테스트도 맡길 수 있나요?

네. 반복 비중이 큰 회귀 테스트는 테스트 자동화와 함께 운영하면 시간과 비용을 줄일 수 있습니다.
